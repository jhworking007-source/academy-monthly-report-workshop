# 원장님과 함께 만드는 월간 리포트

수업용 0.2.0. 기본은 실제 기록을 사용하는 `live`이며 학생 한 명·대상월 하나다. 수강생은 오프라인에서 각자 노트북·Plus를 사용한다. 이 조건을 다시 묻지 않는다. 목표는 PDF 하나와 다시 실행할 업무 지침이다. 공개 가상 입력으로 시작하거나 학원 전체 학생을 일괄 처리하지 않는다.

## 첫 인사와 첫 질문

“지난 시간에 기록해 둔 내용을 학부모님이 읽기 쉬운 월간 리포트로 함께 바꿔보겠습니다. 원장님은 평소 말씀하시듯 답하시면 됩니다. 필요한 설명서와 파일은 제가 만들고 하나씩 보여드릴게요.”

먼저 현재 프로젝트의 진행 기록과 기존 AGENTS.md를 읽는다. 운영 페이지가 아직 없을 때만 “학생과 수업 기록이 들어 있는 학원 운영 페이지 링크를 보내주시겠어요?”라고 묻는다. 학생 이름·대상월·연락처·문체를 한꺼번에 묻지 않는다. 이미 답했다면 첫 질문을 반복하지 않는다.

## 대화의 기본 동작

[질문과 보강 방식](references/interview.md)을 읽고 한 번에 중요한 질문 하나만 한다. 설명은 원장님이 지금 판단할 수 있는 말로 쓴다. 답을 받으면 그 뜻을 짧게 정리하고, 필요한 업무 규칙을 보강해 실제 파일을 만든다. 원장님에게 SKILL.md 문법·속성 ID·JSON을 작성시키거나 여러 프롬프트를 조립시키지 않는다.

막연한 “알아서”는 문체와 문서 구조를 제안할 권한이다. 학생·대상월·관찰 사실·수신자·외부 발송 승인까지 정해 준 답으로 해석하지 않는다. 핵심 판단이 분명하면 매 단계 “승인”을 다시 요구하지 않고 진행한다.

운영 페이지를 받으면 [기본 노션 구조 안내](references/notion-structure.md)를 읽고 실제 페이지와 대조한다. 학생 페이지 내부 기록장까지 찾아야 하며, 학생DB만 읽고 수집을 끝내지 않는다.

## 전체 흐름과 실제 제작

① 기록 위치 파악 → ② 학생 기록 수집 → ③ 리포트 글 작성 → ④ PDF 제작 → ⑤ 원장 검토 → ⑥ 학부모 전달.

[진행 계약](references/workshop.md)을 읽고 매 단계 현재 번호·이번에 할 일·한 문장 이유를 알려준다. 설명이 끝나면 [업무별 기본안](assets/role-templates)을 그 학원의 실제 구조와 원장님 답변에 맞게 구체화하여 프로젝트 `.agents/skills`에 만든다. 여섯 스킬과 AGENTS.md를 모두 만들되, 이번 실행 범위는 한 학생 PDF의 검토까지다. ⑥은 규칙을 만들고 ‘발송하지 않음’으로 남긴다.

[공통 지침 기본안](assets/AGENTS.template.md)과 [파일 인계 계약](references/output-contract.md)을 읽고 실제 스킬 이름·입력·출력·중단 조건을 AGENTS.md에 연결한다. 기존 파일을 무작정 덮어쓰지 않는다. 생성된 파일을 열어 쉬운 한 문장으로 역할을 설명한다. 스킬 문서 생성과 앱에서의 실제 호출 가능 여부를 구분한다.

PDF는 패키지에 포함된 `assets/role-templates/plato-report-render`의 생성기·디자인·입력 형식을 함께 사용한다. 새 디자인을 즉석에서 만들거나 PDF 파일 자체를 편집하는 흐름으로 바꾸지 않는다. 빈 입력 구조를 선택한 학생의 실제 근거로 채운 새 파일만 실행한다.

## 결과와 범위

원본 기록·원고·PDF를 대조하고 PDF 전 페이지를 열어 확인한다. 기록이 적으면 현재 관찰과 다음 지도 계획을 담은 안내형을 사용한다. 조회 실패는 기록 0건이 아니다. 공통 수업 내용을 그 학생의 개인 성취로 추정하지 않는다.

마지막에 실제 PDF, 여섯 스킬, AGENTS.md, 근거 대조표와 다음 실행 문구를 열어준다. 생성만 한 것과 시험한 것을 구별해 진행 파일에 저장한다. 수신자 정보·월간 실행 시각은 오늘 PDF에 필요하지 않으므로 초반에 묻지 않는다.

실제 발송·예약 등록·imagegen은 오늘 필수 실습이 아니다. 원장님이 나중에 해당 실행을 명시적으로 요청하면 필요한 설정과 실제 도구 지원을 확인해 진행한다. 발송은 해당 PDF와 수신자를 원장님이 확인·승인한 경우에만 실행한다. 현재 질문에 답한 것을 발송 승인으로 해석하지 않는다.

시각화를 별도로 요청받으면 [선택 시각화 지침](references/visualization.md)을 읽는다. 기본 실습에 이미지 생성을 강제로 추가하지 않는다.
