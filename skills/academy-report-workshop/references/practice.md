# 가상 실습 입력


모든 기록은 가상. 실제 학생의 성취나 실제 노션 내용으로 소개하지 않는다. 기존 기록장 본문 형식에 입력할 수 있는 교육용 자료이며 원격 DB를 임의 수정하지 않는다.

| ID | 날짜 | 기록 유형 | 실제 말·글로 설정한 가상 원문 | 도움·관찰 조건 |
|---|---|---|---|---|
| E1 | 2026-09-03 | 과제·글쓰기 | 친구가 도와줘서 좋았다. 나도 이런 친구가 있으면 좋겠다. | 별도 이유 질문 없이 작성 |
| E2 | 2026-09-10 | 수업 관찰 | 그 친구는 혼자 먼저 가도 됐지만 같이 가고 싶었던 것 같아요. | 인물의 다른 선택에 관한 대화 |
| E3 | 2026-09-17 | 과제·글쓰기 | 친구가 끝까지 기다려 준 장면이 기억에 남는다. 함께 가는 일이 더 중요하다고 생각했기 때문이다. | E1과 같은 활동. “왜 그 장면이 기억에 남았니?” 질문 뒤 재작성 |
| E4 | 2026-09-24 | 성찰 | 처음에는 좋다고만 썼는데, 지금은 왜 좋은지 알 수 있게 썼어요. | 수정 목적에 관한 자기 설명 |

```text
이 프로젝트의 AGENTS.md와 업무별 스킬을 따라, 제공한 가상 학생 한 명의 2026년 9월 월간 리포트를 제작·검수해줘.
먼저 정보 맵과 수집 범위를 보여주고, 근거 목록→원고→PDF 순서로 파일을 열어줘.
각 평가 문장의 날짜·근거·교사 도움을 내부 검수표에 연결해줘.
비교 가능한 작품만 비교하고, 관찰 지도의 점은 근거 존재로 표시해줘.
마지막 장에는 원장님이 학부모님께 보내는 편지를 넣고 내 말투와 지도 약속을 검토할 수 있게 해줘.
가상 자료임을 내부 근거표와 강의 설명에 명시하고 PDF에는 제작용 표식을 넣지 말고, 수신자 확인·승인 전 발송하지 마.
```

결측 사례는 가상4건에서 내용을 임의 지워 실제 DB처럼 소개하지 않는다. 현재기록 검증본의 조회 기준일·등록5/날짜1/완료0을 명시하거나 별도 “가상 결측 사례”로 분리한다.

## 바로 실행할 입력
[4건 입력](../assets/practice/full.json)과 [0건 입력](../assets/practice/empty.json)은 JSON 형식과 결측 분기를 확인하는 실습용 입력이다. 그대로 출력만 하는 것으로 업무 설계와 근거 검수를 생략하지 않는다. [출처](../assets/practice/출처.md)를 읽고 내부 검수표에 남긴다.
