# 이전 수업의 기본 노션 구조를 읽는 법

2026-10-07 기본 학원 운영 페이지에서 실제 조회한 구조다. 구조 탐색의 출발점이며 수강생이 복제한 DB의 ID나 기록 상태를 고정하는 설정은 아니다. 실제 읽은 구조가 다르면 현재 페이지를 따른다.

## 세 기록 층

1. 운영 페이지의 `학생DB`: `학생 이름`(제목), `소속반`, `학년`, `재원 상태`, `독서 수준`, `글쓰기 수준`, `학습 목표`, `지도 유의사항` 등이 있다. 이름·반·페이지 URL 등 선택에 필요한 최소 목록부터 읽는다. 연락처는 이번 PDF 제작에 필요 없다.
2. 선택한 학생 페이지 **본문 안의 `학생 기록장`**: 별도 DB다. 학생마다 다른 데이터 소스일 수 있으므로 선택한 학생 페이지를 열어 실제 DB·collection을 찾는다. 학생DB에 직접 기록 관계 속성이 없다고 ‘기록 없음’으로 판정하지 않는다.
3. 운영 페이지의 `수업 기록`: `수업명`(제목), `수업일`, `반`, `진도`. `AI 수업 기록`은 입력 양식이며 실제 수업 항목과 구별한다.

## 학생 기록장 속성 대응

| 실제 필드 | 용도와 해석 |
|---|---|
| 기록명, 기록일 | 기록 식별·대상월 필터. 편집일/등록일을 대신 사용하지 않음 |
| 관련 수업 | 공통 수업 페이지로 연결. 필요한 수업 본문을 읽어 원문 확인 |
| 기록 유형 | 과제·글쓰기 / 시험·평가 / 수업 관찰 / 학부모 상담 / 기타 기록 |
| 과제·작품 이미지 | 실제 파일을 읽었을 때만 작품 내용 인용. 읽기 실패 구분 |
| 점수 | 만점·평가 기준 없으면 비율/성장 점수로 변환하지 않음 |
| 집중도, 평가 단계 | 각각 높음·보통·낮음 / 상·중·하. 점수로 임의 환산하지 않음 |
| 평가 상태 | 시작 전 / 진행 중 / 완료. 완료 조건을 실제 옵션으로 확인 |
| 학부모 전달 | 참고 표시. 이 체크 자체가 현재 PDF 발송 승인은 아님 |

월의 범위는 기록일 기준 첫날 이상 다음달 첫날 미만이다. 날짜 없는 기록은 별도로 조회해 월 미확인으로 남긴다. 필터 결과의 빈 목록만으로 전체 기록장이 빈 것으로 단정하지 않는다. 조회가 끝났는지 페이지네이션과 접근 성공을 확인한다.

학생의 `소속반`과 수업의 `반`이 같으면 수업 후보를 찾을 수 있다. 그러나 개인 출석·참여·성취는 증명되지 않는다. 공통 수업 본문과 개인 관찰의 출처를 분리하고, 학생별 원문 근거가 없으면 개인 성취로 쓰지 않는다. 학생DB의 현재 독서/글쓰기 수준 역시 그달의 향상이나 과거 수준과의 비교 증거가 아니다.

## 연결 도구를 선택할 때

현재 Notion 도구 접근을 먼저 확인하고 사용할 수 있는 조회 방식을 쓴다. 이 검수 연결에서는 fetch와 제한된 단일 데이터 소스 query를 사용할 수 있었고 AI 검색/여러 데이터 소스 동시 조회는 제한되었다. 그 기능이 필수라고 가정하거나 업그레이드를 요구하지 않는다. 실제 tool 스키마를 읽어 단일 DB별 조회를 순서대로 수행한다. 키워드 검색 누락을 DB 전체 조회 완료로 표현하지 않는다.

원본 노션은 읽기만 한다. 양식이나 기록장 관계를 바꾸고 기록을 새로 입력해야만 PDF가 만들어지는 구조로 바꾸지 않는다.
