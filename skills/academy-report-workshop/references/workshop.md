# 노드별 학습과 실행 계약

## 시작과 진행 상태
학습 모드에서는 파일 생성 순서와 학습자에게 보여주는 순서를 일치시킨다. 사전 환경 점검은 가능하나 업무 스킬을 일괄 복사하지 않는다. 운영 페이지에서 구조만 사전 조회하고 노션 안내의 학생 개인 기록장·수업 DB 구분을 적용한다.

진행 현황.md에 노드별로 역할 설명 / 원장님 답변 / 작성한 스킬 경로 / 공개한 핵심 규칙 / 시험 진행 응답 / 실행 결과 / 다음 노드를 기록한다. 시작 상태는 설계 전이다. 파일 생성과 학습자 확인은 별도 상태다.

## 각 노드의 설계 질문과 작은 시험

| 노드와 스킬 | 먼저 설명할 입력 → 역할 → 출력 | 쉬운 설계 질문 예시 | 스킬을 보여주고 응답받은 뒤 할 시험 |
|---|---|---|---|
| ① academy-map | 운영 페이지 → DB와 연결 찾기 → 정보 맵 | “학생 개인 기록과 수업 기록을 모두 찾되 상담 기록도 위치를 표시할까요? 상담 내용은 별도 확인 전 리포트에 넣지 않는 방식입니다.” 실제 구조에 맞게 질문 수정 | 정보 맵 생성. 학생→개인 기록장→수업의 연결 한 개를 보여줌 |
| ② collect-records | 정보 맵·학생·월 → 해당 기록만 모으기 → 근거 목록 | “함께 들은 수업 내용과 이 학생이 실제로 한 일을 나눠 모을까요?” 개인 성취로 혼합하는 선택지는 제안하지 않음 | 선택 학생·월의 기록만 수집. 출처 있는 관찰 한 건과 공통 수업 한 건의 차이를 보여줌 |
| ③ write-report | 근거 목록 → 학부모용 글로 바꾸기 → 원고·근거표 | “기록이 적은 항목은 확인된 모습과 다음 지도 계획을 쓸까요, 그 항목을 뺄까요?” | 원고만 작성. 원문과 실제 리포트 문장 한 쌍을 보여줌 |
| ④ plato-report-render | 원고 → 제공 양식에 배치 → PDF | “비교할 작품이 없으면 비교 대신 현재 모습·다음 지도 중심의 안내형으로 만들까요?” | 해당 생성기로 PDF 제작. 결과를 열고 볼 페이지 안내 |
| ⑤ review-report | 원문·원고·PDF → 사실·배치 확인 → 검수표 | “원장님이 마지막으로 특히 확인할 부분은 성장 표현, 작품 비교, 마지막 편지 중 무엇인가요?” | 모든 페이지를 검수하고 선택한 부분을 짚음. 원장님의 PDF 확인을 기다림 |
| ⑥ send-report | 검수 PDF·원장 승인 → 수신자 대조 → 발송 이력 | “PDF와 받는 분을 원장님이 확인한 뒤 보내고 이미 보낸 건은 멈추게 할까요?” | 실제 발송 없이 승인 없음/이미 발송됨 두 상황의 처리 규칙을 설명하고 확인 |

질문은 예시다. 이미 답이 있으면 재질문 대신 반영한 답을 보여준다. ② 시작에서 학생과 월이 없으면 각각 한 질문씩 받은 뒤 수집 기준을 설명·설계한다. 정보 수집만 끝났다고 설계를 생략하지 않는다.

각 스킬 작성 후 링크 + 3~5줄 규칙 + 반영한 원장님 말 + 시험/수정 선택을 보여주고 **반드시 다음 응답을 기다린다**. 해당 스킬 실행 전 확인 경계는 한 번이면 충분하다. 실행 후 다음 노드 설명·설계 질문으로 이어갈 수 있다. 예: ③ 원고가 완성되어도 ④ 스킬을 공개하고 응답받기 전 PDF 생성 금지.

## AGENTS.md 연결 학습

여섯 노드의 학습 후 “지금까지는 업무별 설명서를 만들었습니다. AGENTS.md는 어떤 순서로 읽고 다음 업무에 무엇을 넘길지 정하는 연결 규칙입니다”라고 설명한다.
“기록 조회 실패나 검수 오류가 있으면 그 지점에서 멈추고 원장님께 알리도록 연결할까요?”를 묻는다. 기존 대화에서 해당 답이 분명하면 그 답을 인용한다.
실제 여섯 파일과 입력·출력 경로로 AGENTS.template.md를 구체화하여 공개하고, 핵심 연결 3~5줄을 보여준다. “이 연결대로 시험해볼까요, 수정할 부분이 있나요?”로 기다린다.

응답 뒤 새 AGENTS.md와 여섯 파일을 읽고 현재 학생·월의 산출물이 연결되는지 확인한다. 앞 단계에서 이미 실행한 원본·PDF가 그대로 유효하면 재조회·재생성 대신 파일과 출처를 따라 연결을 검증한다. 입력이나 규칙이 바뀌었다면 영향을 받는 단계부터 다시 실행한다. 발송은 생략 상태, 예약은 미등록 상태로 남긴다. 연결 점검을 예약·발송의 실제 성공으로 부르지 않는다.

## 기록 상태
- 충분: 비교 자료의 날짜·과제·교사 도움과 생성기의 full 조건을 확인.
- 일부: 확인된 관찰만 쓰고 제안은 분리. limited 선택.
- 없음: 대상월 전체 정상 조회 후 실제 0건인 경우만. 성취를 만들지 않고 기록·지도 계획 안내.
- 조회 실패: 접근·페이지네이션·본문 확인 실패는 0건이 아님. 복구하거나 보류.
날짜 없는 기록을 대상월로 추정하지 않고, 공통 수업을 개인 성취로 옮기지 않는다.

## 학습 완료
여섯 업무마다 설명·학습자 판단 반영·실제 파일 공개·시험 또는 문서 점검 기록이 있어야 한다. PDF 전 페이지 검수와 원장님 확인, AGENTS.md 연결 확인을 포함한다. 빠진 학습 단계가 있으면 파일이 모두 존재해도 “학습 완료”라고 하지 않는다.
진행 현황에서 파일 생성/실행 확인/사람 확인 대기/미설정/보류를 구별한다. 수신자는 PDF 실습에서 미설정이어도 된다. 현재 설치된 SKILL.md를 직접 읽어 실행한 것과 앱의 자동 스킬 호출 검증은 구별한다.
