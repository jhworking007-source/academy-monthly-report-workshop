# 실제 학생 한 명으로 진행하는 계약

## 시작과 환경

기존 진행 파일을 읽고 모르는 항목만 확인한다. 튜터 설치와 PDF 템플릿 파일의 존재, 현재 앱의 파일 실행·노션 접근을 확인한다. PDF 생성기는 패키지 안에 포함되어 있어 수강생이 따로 디자인을 만들 필요가 없다. 필요한 로그인·권한은 실제 화면을 열어 사람이 할 조작만 안내한다. 비밀번호나 토큰을 채팅으로 받지 않는다.

[기본 노션 구조 안내](notion-structure.md)를 읽어 학생 페이지 본문 안의 별도 기록장을 찾는다. 환경이 되면 실제 운영 페이지를 읽는다. 모든 DB의 이름·속성·관계와 학생별 기록장 위치를 파악하되 모든 학생의 기록 본문을 수집하지 않는다. 학생을 선택한 후 한 명의 대상월 본문과 연결된 수업 자료만 수집한다. 월과 학생이 정해지기 전에는 리포트를 생성하지 않는다.

## 단계마다 설명서도 함께 만들기

| 전체 흐름 | 튜터가 설명할 쉬운 뜻 | 실제 산출물과 다음 확인 |
|---|---|---|
| ① 기록 위치 파악 | 학생 이야기와 수업 기록이 어디에 있는지 찾습니다. | academy-map 스킬, 정보 맵. 선택한 학생의 기록장으로 연결되는지 확인. |
| ② 학생 기록 수집 | 그 학생의 그달 기록만 모읍니다. | collect-records 스킬, 근거·조회 범위·부족한 정보. 학생과 날짜, 조회 완료 여부 확인. |
| ③ 리포트 글 작성 | 기록을 학부모님이 이해할 말로 정리합니다. | write-report 스킬, 원고·문장별 근거표. 관찰과 제안을 구별. |
| ④ PDF 제작 | 원고를 제공된 양식에 넣습니다. | plato-report-render 스킬과 리소스, 새 입력 JSON·PDF. 원문과 출력 대조. |
| ⑤ 원장 검토 | 다른 학생 이야기나 과장이 없는지 살펴봅니다. | review-report 스킬, 내용·디자인 검수표. 원장님이 PDF를 직접 확인. |
| ⑥ 학부모 전달 | 확인한 파일을 확인한 수신자에게만 보냅니다. | send-report 스킬과 승인 규칙. 오늘은 규칙만 작성하며 실제 전송은 하지 않음. |

스킬 기본안에 해당 학원에서 실제 확인한 DB ID·속성 대응·날짜 기준·원장님 문체·인계 파일·기록 부족 규칙을 반영한다. 단순 복사를 맞춤 설계 완료로 보고하지 않는다. 여섯 스킬이 마련되면 AGENTS.md로 연결하고 실제 학생 하나의 수집→원고→PDF→검수를 그 파일들에 따라 실행한다. 처음부터 여섯 스킬 원문을 채팅에 길게 던지지 않는다.

## 기록 상태별로 할 일

| 상태 | 판정 조건 | 실제 행동 | 결과 |
|---|---|---|---|
| 기록 충분 | 대상 학생·월이 확인되고 사용 가능한 관찰과 비교 자료가 있음 | 근거를 고르고 비교 가능성을 확인. 생성기의 full 조건도 별도로 충족해야 full 선택 | 근거 있는 월간 리포트. 비교 불가 영역은 현재 모습만 |
| 기록 일부 | 쓸 수 있는 사실은 있지만 양·날짜·작품 또는 비교 근거가 부족함 | 확인된 사실만 사용. 부족한 항목을 짧게 알리고 다음 지도는 제안으로 작성. limited 선택 | 현재 관찰과 다음 지도 계획을 담은 안내형 리포트 |
| 기록 없음 | 대상월·범위를 끝까지 정상 조회했고 사용 가능한 기록이 0건임 | 성장·수업 참여·성취를 쓰지 않음. 사실 확인 범위와 앞으로 기록·지도할 방향만 안내 | 기록 부족을 정직하게 알리는 안내형. 정상 full 완성으로 집계하지 않음 |
| 조회 실패 | 권한·연결·첨부 또는 페이지네이션 실패로 필요한 기록을 확인하지 못함 | 연결 복구를 먼저 안내. 같은 실제 학생 자료를 원장이 내보내 제공할 수 있는지 확인하거나 단계 보류 | PDF 생성 보류 또는 출처를 명시한 실제 자료 대체. 0건과 가상 기록으로 변환 금지 |

DB 항목이 많다는 이유만으로 충분하다고 판단하지 않는다. 날짜 없는 기록을 대상월로 추정하지 않는다. 공통 수업에서 “오늘 토론을 했다”는 말은 수업 활동이며, 해당 학생의 토론 능력이나 참여를 입증하지 않는다. 학생별 연결과 관찰이 없는 성과를 붙이지 않는다.

## 결과를 보여주며 마무리

수강생이 파일을 확인할 때는 한 화면에 한 가지를 짚는다. “이 파일은 다음 달에도 같은 기준으로 기록을 모으는 설명서입니다.” “이 문장은 12일 수업 기록에서 왔습니다.”처럼 실제 근거와 결과를 연결한다.

최종 PDF의 모든 페이지를 확인하고 다른 학생 잔존·기간·날짜·과장·문구 넘침·한글·편지를 대조한다. 오류를 고치고 새 버전으로 만든다. 수신자는 아직 미설정이어도 PDF 제작 완료는 가능하다. 다만 ‘발송 준비 완료’나 ‘자동화 실행 검증 완료’로 확대하지 않는다.

예약 규칙은 AGENTS.md에 월간 시작→지난달 수집→PDF→검수→승인 대기로 적는다. 실제 일정은 미설정으로 남긴다. 원장님이 요청할 때 일시·시간대·프로젝트·도구 지원을 확인하고 등록한다. imagegen 시각화도 요청 시에만 실제 만들어진 파일과 상태를 바탕으로 한다.

날짜가 없어 어느 달인지 모르는 기록은 0건 판정의 근거가 아니다. 확인되지 않은 날짜·본문·평가 상태를 별도 목록에 남기고 ‘일부 정보 부족’ 또는 ‘확인 보류’로 구별한다. 조회 실패가 해결되지 않으면 완전한 월간 수집이라고 하지 않는다.
