# 쉬운 질문으로 업무 규칙을 함께 만들기

질문은 입력값 수집과 함께 원장님이 업무 기준을 정하도록 돕는 수단이다. 한 번에 질문 하나, 선택지 2~3개와 자유 답변을 제공한다. 전문 용어 대신 실제 학원 장면을 쓴다.

## 원고 노드의 대화 예시

튜터: “지금은 [③ 글 작성]입니다. 앞에서 모은 기록을 학부모님께 전할 글로 바꾸는 설명서를 만들겠습니다. 기록이 적은 항목은 어떻게 할까요? ① 확인된 모습과 다음 지도 계획 적기 ② 해당 항목 생략하기. 저는 ①을 추천합니다. 확인되지 않은 성장을 만들지 않으면서 앞으로의 지도를 전할 수 있어요.”

원장님: “기록대로 정리해줘.”

튜터: “확인된 사실을 중심으로 쓰자는 뜻을 반영했습니다. 부족한 부분은 성취 문장으로 채우지 않고 다음 지도 제안으로 구분했습니다.”
실제 write-report/SKILL.md를 작성하고 링크와 핵심 규칙을 보여준다.
“기록을 읽는 일은 수집 스킬이, 학부모용 글로 바꾸는 일은 이 스킬이 맡습니다. 이 규칙으로 원고를 시험해볼까요, 바꾸고 싶은 점이 있나요?”
**여기서 응답을 기다린다. 원고나 PDF를 미리 만들지 않는다.**

원장님: “해봐.”

튜터: 현재 스킬을 읽고 원고만 작성한다. 실제 기록 한 구절과 리포트 문장 한 구절을 보여주며 사실과 제안을 구별한다. 이어 ④ 역할과 설계 질문 하나로 끝낸다. PDF는 ④ 파일을 보여주고 학습자 응답을 받은 뒤 생성한다.

## 모호한 답변

| 답변 | 처리 |
|---|---|
| 알아서 / 기록대로 | 현재 질문의 추천 규칙을 명시하고 현재 스킬만 작성·공개 |
| 모르겠어요 | 학원 사례 두 개와 추천안으로 풀어줌. 이해도 채점은 하지 않음 |
| 보기 좋게 | 원고 단계라면 따뜻하고 짧은 문체, PDF 단계라면 기존 템플릿 배치 원칙으로 구체화 |
| 많이 성장했어요 | 실제 장면을 확인. 근거 없으면 원장 판단으로 구분 |
| 기록 없으면 좋은 말 채워줘 | 일반 지도 계획은 제안으로 작성. 참여·감정·성취를 발명하지 않음 |
| 다음 / 해봐 | 현재 공개된 스킬의 시험 또는 결과 확인. 이후 노드 전체 생략으로 확대하지 않음 |
| 빨리 끝내줘 | 설명을 줄이고 추천안 제공. 명시적 학습 생략 요청이 아니면 파일 공개 유지 |

## 보여주는 양과 이어하기

스킬 전체를 채팅에 쏟지 않는다. 실제 파일 링크와 입력·할 일·결과·예외를 담은 3~5줄을 보여준다. queued는 표시 완료가 아니다. 학생·월·운영 페이지와 이미 답한 판단은 다시 묻지 않는다.

이미 PDF와 여섯 파일이 있어도 학습 확인 기록이 없으면 교육 완료가 아니다. 결과를 보존하고 “파일은 만들어져 있으니 첫 업무부터 역할과 규칙을 함께 살펴보겠습니다”라고 안내한다. 현재 스킬만 읽고 원장님의 판단을 반영해 개정한다. 일괄 재생성하지 않는다.
