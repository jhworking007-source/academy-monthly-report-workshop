# 학원 정보 맵

입력: 사용자가 지정한 운영 페이지와 읽기 가능한 Notion 연결.
운영 페이지의 하위 페이지와 중첩 DB를 실제로 읽고 페이지네이션을 끝까지 처리한다. 원본 DB/데이터 소스 ID와 연결 뷰를 구별하고 중복을 제거한다. 학생별 기록장은 서로 다른 DB일 수 있다.
DB별 이름·ID·URL·속성명·유형·관계 대상·날짜 필드·평가 상태 옵션을 적는다. 학생ID→학생 페이지→기록장 ID의 연결과 공통 수업DB를 표시한다. 다른 속성 이름의 대응과 접근 실패 목록을 별도로 남긴다.
결과: 01 정보 맵.md와 조회 범위·시각·성공/실패 근거. 빈 DB를 확인하려면 조회 성공과 마지막 페이지까지 확인해야 한다.
완료: 원장님이 학생 한 명의 기록 위치를 확인할 수 있고 접근 불가와 빈 자료를 구별할 수 있다. 구조 변경은 조회·보고만 하며 원본 노션을 임의 재구성하지 않는다.

실제 학생 한 명과 대상월 하나를 사용한다. 연결 실패를 가상 기록이나 기록 0건으로 대체하지 않는다. 공통 수업 기록은 해당 학생과의 연결이 확인된 내용만 개인 관찰로 사용한다. 수업 전체의 활동 소개와 학생 개인의 수행을 구별한다.

기본 양식은 운영 페이지의 학생DB·수업 기록, 그리고 각 학생 페이지 본문 안의 학생 기록장으로 나뉜다. 이름이 같은 기록장도 실제 데이터 소스를 따로 확인한다. 관계 속성이 학생DB에 없다는 이유로 개인 기록을 누락하지 않는다. 실제 학원 구조를 확인한 뒤 필드 대응을 이 스킬에 기록한다.
