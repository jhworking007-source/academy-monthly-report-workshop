# 플라톤 월간 리포트 PDF 제작

사용자에게 학생별 내용 파일과 결과 PDF 위치를 보여준다. 실행 전에 어떤 내용을 배치할지 한 문장으로 설명한다. Adobe 플러그인 없이 이 패키지의 생성기를 사용한다.

## 입력 준비
[입력 항목 목록](입력 항목 목록.md)과 [JSON 형식](입력 형식.schema.json)을 읽는다. [내용 입력.json](내용 입력.json)은 필드 구조와 글자 분량을 참고하는 초기 파일이다. 기존 작품·평가·편지를 새 학생의 사실로 재사용하지 않는다.

학생별로 새 JSON을 복사하고 학생 이름·학년·반·대상월·작품·관찰·지도·원장 편지를 검증된 원고로 채운다. 같은 정보가 여러 text 항목에 있으면 모두 일치시킨다. 제목·일반 라벨·색·좌표는 원장 요청이 없으면 유지한다. 원문·날짜·교사 도움·판단 근거는 별도 내부 근거표에 연결한다.

full은 4개 대표 관찰, 6영역 관찰 지도, 비교 가능한 작품 2개, 편지 5문단이다. records[0]과 records[2]가 같은 활동의 첫 글·재작성인지 확인한다. 기록이 부족하거나 비교 조건이 맞지 않으면 limited를 사용하거나 별도 레이아웃 변경 요청으로 분리한다. 근거를 네 건에 맞춰 발명하지 않는다. limited는 records 빈 배열도 허용한다.

counts는 실제 조회에서 얻은 전체·날짜 있음·완료 상태 건수다. 숫자와 막대 폭이 같이 바뀐다. 날짜·평가 상태가 불명확한 내용을 평가 근거로 승격하지 않는다. 관찰 지도 점은 기록 존재이며 능력 점수가 아니다.

PDF에 가상 기록·디자인 확인용 시안·원장 검토용 편지 예시 등의 제작 안내를 추가하지 않는다. 실습 자료의 출처·가상 여부는 사용자에게 설명하고 내부 근거표에 보존한다.

## 실행
패키지 폴더를 기준으로 실행한다.

`uv run generate.py 학생별내용.json 월간리포트.pdf --variant full`

기록 부족형은 `--variant limited`. 실행 환경에는 Python3.11 이상과 Windows 맑은 고딕이 필요하다. uv가 의존성을 준비한다. 맑은 고딕이 없으면 사용자 OS에 맞는 한글 글꼴 경로를 layout.py에서 지정하고 재검수한다. 이 버전은 Windows에서 검증했다.

내용 넘침 오류는 해당 원고를 축약하고 다시 생성한다. 글꼴을 임의로 작게 바꾸거나 출력된 일부 파일을 최종본으로 전달하지 않는다. 생성 중 오류가 나면 기존 PDF는 보존된다.

## 결과 확인
전체 페이지를 렌더해 겹침·잘림·한글·순서를 확인한다. 원고와 출력의 학생·월·날짜·작품·편지·기록 수·관찰 점을 대조한다. 생성한 PDF, 원고 입력 JSON, 검수 결과와 파일 해시를 함께 인계한다.

이 스킬의 완료는 PDF 생성·검수다. 학부모 발송·예약을 자동 실행하지 않는다. 원장 승인 및 수신자 대조는 후속 발송 단계가 담당한다.

학생 이름(student_name), 학년·반(class_label), 대상월(report_month: YYYY-MM)을 한 번 입력하면 표지와 본문 머리말의 이름·연월·월간 기간이 함께 바뀝니다. 작품별 날짜와 원고에 서술한 날짜는 근거와 별도로 대조합니다.
