# 학원 월간 리포트 운영 지침
## 시작
학생 페이지 ID와 대상월을 모든 단계의 공통 기준으로 사용합니다.
매 실행 정보 맵을 조회·비교하고 바뀐 구조를 먼저 반영합니다.
## 순서와 결과 인계
1. academy-map: 운영 페이지에서 정보 맵과 접근 불가 목록을 만듭니다.
2. collect-records: 정보 맵에서 학생별 근거와 결측 목록을 만듭니다.
3. write-report: 근거·해석·제안을 구별한 원고와 원장 편지를 만듭니다.
4. plato-report-render: 확정 원고를 세로형 템플릿에 배치해 PDF를 만듭니다.
5. review-report: 기록·원고·PDF·학생·월·수신자를 대조합니다.
6. 원장에게 PDF와 수신자 목록을 보여주고 해당 항목 승인을 기다립니다.
7. send-report: 승인된 PDF와 수신자만 대조해 전달하고 결과 이력을 남깁니다.
## 공통 판단
앞 단계 결과가 없거나 검수에 실패하면 다음 발송 단계로 넘어가지 않습니다.
기록 부족은 안내·일반 활동 제안으로 처리하되 성취·감정·상담 이력을 만들지 않습니다.
조회 실패는 기록 없음과 구별하고 수집을 복구하거나 보류합니다.
교사 도움을 받은 재작성을 독립 수행 향상으로 확대하지 않습니다.
원장 편지는 확인한 장면, 지도 방향, 가정과의 협력으로 쓰고 원장이 검토합니다.
## 승인과 재실행
승인은 학생 ID·대상월·PDF 버전과 해시·수신자에 연결합니다.
PDF 또는 수신자가 바뀌면 이전 승인을 사용하지 않고 재검수·재승인합니다.
같은 학생·같은 월의 발송 이력을 먼저 확인합니다.
완료 건은 재발송하지 않습니다. 미확인은 화면을 확인하며 자동 재전송하지 않습니다.
## 예약
월간 예약은 지난달 기록의 제작·검수와 승인 대기까지 시작합니다.
승인 후 해당 항목의 발송만 재개합니다.
로컬 예약은 컴퓨터 전원·데스크톱 앱 실행·프로젝트 폴더 접근이 필요합니다. 컴퓨터 사용은 지원 지역·플러그인·로그인·권한을 확인합니다. Windows 실행은 화면 잠금 해제·인터넷·대상 앱 전면 표시 조건을 점검합니다.
