# 학원 월간 리포트 공통 지침

## 오늘의 기본 범위

실제 학생 한 명과 대상월 하나의 리포트를 제작하고 검토합니다. 학원 운영 설정.md에서 확인한 학생 ID·대상월·운영 페이지를 사용합니다. 이 값이 없거나 모호하면 필요한 것 하나만 질문합니다. 가상 입력·다른 학생·다른 달로 대체하지 않습니다.

여섯 업무 스킬은 실행 설명서이며 이 문서는 연결 규칙입니다. 문서 생성만으로 도구 실행·예약 등록이 완료되지는 않습니다. 실행 시 실제 스킬 파일을 읽고 수행합니다. 플랫폼에서 여러 에이전트 실행이 지원된다고 확인하지 않았다면 별도 프로세스가 돌아간다고 설명하지 않습니다.

## 순서와 결과 인계

1. academy-map: 운영 페이지의 DB 구조·학생 기록장·수업 연결을 읽어 01 정보 맵.md를 만듭니다.
2. collect-records: 선택한 학생과 대상월의 근거.json, 조회 범위와 부족한 정보 목록을 만듭니다.
3. write-report: 근거가 있는 원고와 원장 편지를 작성하고 사실·해석·제안을 구별합니다.
4. plato-report-render: 제공된 생성기와 디자인에 새 학생 입력을 넣어 리포트.pdf를 만듭니다.
5. review-report: 실제 기록·원고·PDF 전 페이지를 대조하고 검수.md에 남깁니다. 원장님에게 PDF를 열어줍니다.
6. send-report: 이번 수업에서는 지침만 마련합니다. 별도 발송 요청과 해당 파일·수신자의 확인·승인이 없으면 실행하지 않습니다.

월별 작업/<대상월>/<학생ID>/에 입력·원고·PDF·검수 결과를 연결하고, 진행 현황.md에 현재 단계와 다음 행동을 저장합니다. 이 기본안의 이름·경로는 실제 생성한 스킬 및 파일과 대조해 확정합니다.

## 공통 판단

- 학생과 날짜를 확인하고 필요한 범위를 끝까지 조회합니다. 접근 실패·확인 불가를 기록 0건으로 바꾸지 않습니다.
- 부족한 기록은 있는 사실만 쓰고 다음 지도는 제안으로 구별합니다. 성취·감정·수업 참여·상담 이력을 발명하지 않습니다.
- 공통 수업 내용은 학생 개인의 수행과 구별합니다. 교사의 도움을 받은 재작성을 독립 수행의 향상으로 확대하지 않습니다.
- 기록이 충분해 보여도 현재 full 템플릿의 관찰·비교 조건이 맞지 않으면 limited를 사용합니다. 수치를 채우기 위해 근거를 만들지 않습니다.
- PDF 원고·학생·월·해시를 연결하며 오류가 나면 이전 결과를 보존하고 수정 후 다시 검수합니다.
- PDF만 만드는 단계에서 수신자나 예약일이 미설정이어도 제작을 중단하지 않습니다. 그 상태를 발송 준비 완료로 표현하지 않습니다.

## 나중에 발송할 때

원장님이 발송을 요청하면 실제 수신자와 최종 PDF·발송 문구를 보여주고 해당 항목의 승인을 확인합니다. 승인은 학생 ID·대상월·PDF 버전과 해시·수신자에 연결합니다. 바뀌면 다시 확인합니다. 같은 학생·월의 이력을 먼저 확인하고 완료 건은 재발송하지 않습니다. 미확인 건은 화면 확인 없이 자동 재전송하지 않습니다.

## 나중에 월간 예약을 사용할 때

원장님이 요청한 일정·시간대·프로젝트와 현재 도구 지원을 확인합니다. 지정 시각에는 지난달 기록 수집→원고→PDF→검수→원장 확인 대기까지 시작하도록 설정합니다. 실제 등록 결과와 다음 실행 시각을 확인한 경우에만 예약 등록으로 기록합니다. 생성한 문서에 일정이 적혔다는 이유로 예약됐다고 하지 않습니다. 실제 첫 실행 성공 여부는 별도로 확인합니다.
